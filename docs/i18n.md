# i18n — read when you touch any user-facing string

Every string a person reads lives in the catalog. Nothing readable stays in JSX.

## The shape

- **next-intl, no locale in the URL.** The app sits behind sign-in, so a cookie is
  enough. `proxy.ts` knows nothing about locale and must stay that way.
- **`apps/app/i18n/config.ts` owns the locale list, the default and the cookie.**
  `pt-BR` is the default. `en` is the fallback. Add a locale there, nowhere else.
- **`apps/app/i18n/request.ts` reads the cookie and merges the catalogs.** English
  is merged underneath the active locale, key by key, so a missing pt-BR key shows
  English instead of a raw key. A release never waits on a translation.
- **`apps/app/i18n/actions.ts` writes the cookie.** It is the only `"use server"`
  file in the app.

## The catalog

One directory per locale, one file per namespace:

```
messages/
  en/     nav.json  deals.json  ui.json  …
  pt-BR/  nav.json  deals.json  ui.json  …
```

Rules:

- **A namespace is an area, not a component.** `deals`, `companies`, `settings`.
- **`en` and `pt-BR` must have the same key set.** A key in one and not the other
  is a bug, even though the fallback hides it.
- **`apps/app/i18n/GLOSSARY.md` is the pt-BR vocabulary.** One word per concept.
  Do not reach for a synonym because a sentence reads better.
- **Plurals are ICU, never string concatenation.**
  `"{count, plural, one {# negócio} other {# negócios}}"`. English hides agreement
  that Portuguese does not, so `${n} deal${n === 1 ? "" : "s"}` has no translation.

## Reading a string

```tsx
"use client";
const t = useTranslations("deals");
```

```tsx
const t = await getTranslations("deals");
```

`generateMetadata` is async and reads the catalog the same way. A page that still
exports `const metadata` with an English literal is not translated.

## What does not go in the catalog

- **User data.** Company names, contact names, custom field labels. A workspace
  admin types those; there is no key to swap.
- **`error.message` from the API.** Those strings are thrown in `apps/api` and
  arrive over the wire. Do not wrap them in `t()` — that produces a missing key,
  not a translation. See the Issues note in `docs/api.md` when this is fixed.
- **Codes.** `DealStage.CLOSED_WON` is a code. The label for it is a catalog key
  named after the code. `lib/deal-stage.ts` is the pattern: the module keeps
  order, tone and colour; the catalog keeps the words.

## `packages/ui` takes no i18n dependency

The package ships English defaults and accepts overrides through a provider.

- `packages/ui/src/components/labels.tsx` holds `UI_LABELS`, the English defaults.
- A component reads one with `useUiLabel("close")`.
- `apps/app/app/layout.tsx` wraps the tree in `UiLabelsProvider` and feeds it the
  `ui` namespace.

Never import `next-intl` inside `packages/ui`. A new shared string is a new key in
`UI_LABELS` plus the same key in `messages/*/ui.json`.

## Dates, numbers and money

Formatting is `Intl`, not the catalog. Pass the locale.

- `formatMoney`, `formatMoneyCompact`, `formatPercent`, `formatDay` in
  `packages/ui/src/lib/format.ts` all take a locale. Passing none means the
  system locale, which is not the app locale — pass it.
- `components/local-date-time.tsx` renders a server fallback and rewrites it in
  the browser, because only the browser knows the timezone. Both halves format
  with the app locale, and relative time comes from `Intl.RelativeTimeFormat`.
  There is no English in that file. Keep it that way: the hydration script is a
  string literal, so any word added there has to be translated twice.
